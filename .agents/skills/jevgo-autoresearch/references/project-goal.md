# JevGO 总体目标与研究协议

本文件是 autoresearch 框架的长期项目记忆。首次整理：2026-10-14。稳定目标与当前实现状态分开维护；建议的实现和对比默认值允许根据实验调整，但要记录变化及可比性影响。

## 1. 已确定的研究目标与范围

给定一个问题或交互任务，使用通用知识建立显式研究状态，让 LLM 提议假设与行动，JEV 辅助评估，MCTS 分配搜索预算，在真实命令行或 benchmark 环境中执行实验、积累证据，直到足以回答问题、完成任务或预算耗尽。

首要研究问题：**在不训练模型参数的条件下，这个循环能否改善推理时的精度、任务成功率和研究结论的证据质量，其提升是否值得额外成本？** 是否有效必须由对比实验回答，不能预设完整方法一定优于基线。

用户已确定：

- 第一阶段只做推理时方法，默认 `learning_mode: none`。
- 保留 `none | value_only | policy_only | joint`，未来可借鉴 AlphaGo Zero 学习长期价值、微调策略或同时训练；本轮不隐式启用训练。
- 目标 benchmark 为 MiniGrid、ALFWorld、ScienceWorld、DiscoveryWorld；它们的任务结构和观测形式不同，分别报告效果。
- 选择 AutoTrust 的 JEV 27B 文本、27B VL、9B，以及 SemIf（原 OpenJev）作为模型/评估实现组合。SemIf 是冻结模型 logits 的评分实现，不是与某一独立训练权重等价的名称。
- 环境和模型权重已由用户准备。版本、底座、revision、路径和实际使用组合读取项目根目录的 `configs/jevgo.yaml`、`configs/weights-manifest.json`；不得由简称推断底座，或因为本文件重建环境、重新下载权重。
- 开始 autoresearch 相关算法实现前，必须先说明本次工作在整个项目中的位置。

环境可用、权重存在、组件可运行、端到端闭环完成、完整评测完成是不同状态。用户报告已安装环境和权重不代表框架或 benchmark 实验已完成。

## 2. 核心循环及环节契约

| 编号 | 环节 | 主要输入 → 输出 |
| --- | --- | --- |
| AR-0 | 问题定义与初始化 | 问题/目标、可用观测、通用知识、成功条件与预算 → 初始显式研究状态和环境实例 |
| AR-1 | 选择分支 | 当前搜索根、树/图及访问统计 → 待扩展节点和路径 |
| AR-2 | 提议与筛选 | 节点状态 → LLM 采样的候选假设/行动、JEV 评分、保留候选及选择依据 |
| AR-3 | 实验具体化 | 保留的研究意图 → 操作序列、前置条件、预期观测、失败判据与预算估计 |
| AR-4 | 真实执行 | 可执行操作及其对应环境状态 → 原始观测、工具/环境反馈、执行状态与实际成本 |
| AR-5 | 证据与状态更新 | 原始观测、历史状态及 JEV 相关性评价 → 可追溯发现、反证、不确定性、后继研究状态 |
| AR-6 | 评估与回传 | 叶节点、任务反馈、可选后续模拟 → 明确语义的回报/价值估计及路径统计更新 |
| AR-7 | 停止或继续 | 状态、客观成功信号、JEV 辅助判断与剩余预算 → 继续搜索、提交行动/实验，或输出答案和停止原因 |

对应原始设想：第 1 步为 AR-0；第 2 步为 AR-2；第 3 步为 AR-3；第 4 步为 AR-4；第 5 步为 AR-5；第 6 步为 AR-7。AR-1 和 AR-6 补充了 MCTS 的分支选择与回传。

一次搜索迭代按 AR-1 → AR-6 运行；AR-7 决定是否继续。环境行动型任务在预算内搜索后提交所选行动，再围绕实际获得的状态更新搜索根；研究型任务可连续提交实验、积累证据。不得重复执行已在同一真实轨迹中生效的动作，或把多个模拟分支都描述成真实轨迹。

AR-3 在动作已原子化时可以很薄；语义接口仍需明确。候选假设是关于世界的主张，行动是获取证据或改变状态的操作，两者不可混用。

## 3. 显式状态和证据边界

建议的最小状态契约（具体类名和存储格式在实现时确定）：

- 任务定义、成功条件、剩余预算和版本标识。
- 观测历史、已执行动作、实验记录与证据来源。
- 通用先验、待验证假设、实测事实、推导结论及其不确定性。
- 已确认的约束、失败尝试、反证、未解决问题。
- 当前环境实例/分支标识，以及可用的快照或重放句柄。

环境真实状态、agent 可访问的观测/信念、搜索统计是不同对象。部分可观测任务不得把隐藏环境状态泄露给候选生成器或 JEV；快照可用于恢复执行，不自动成为模型可见信息。

LLM 可以总结或提出推导，但不能将未经验证的内容升级为实测事实。JEV 可以评估相关性、可信度和有用性，不能制造证据。失败实验和反证可能非常有价值，不按“是否支持当前假设”决定保留。

保留原始实验日志；限制上下文长度时只压缩 agent 的工作记忆，并保留可追溯引用。冲突证据要保留来源和适用条件。

## 4. MCTS 与 AlphaGo 借鉴的边界

框架应包含选择、扩展、叶节点评估/模拟和路径回传。只生成多个候选、全部执行后保留高分项，尚不足以称为 MCTS。

建议维护边统计 `P(s,a)`、`N(s,a)`、`W(s,a)`、`Q(s,a)`，用 UCT/PUCT 一类规则在利用与探索之间分配预算。具体公式、归一化和超参数由实现确定并记录：

- `P` 是候选上的搜索先验；来自 LLM 采样频次、logprob 或 JEV 排序时，说明构造与归一化方式。
- `N/W/Q` 随实际搜索回传更新；明确回报方向、尺度、折扣、代价和一次更新的样本来源。
- 叶节点评估可以来自真实终局反馈、后续 rollout，或明确标注的启发式价值；没有训练也可做搜索。
- MCTS 按预算探索部分候选，并逐渐扩展；“执行所有候选”仅作为另一个搜索策略或消融选项。
- 优先采用保留探索机会的软排序/有限剪枝；硬删除需有明确无效性依据或作为可配置且经过验证的设计。低先验不等于没有信息价值。

JEV 的“候选合理性”“新发现有用性”“当前任务是否完成”和“未来累计回报”必须区分语义、提示和输出字段，可以共享模型后端。未经验证的即时评分不能直接当作经过训练或校准的长期价值 `V(s)`。

未来的 AlphaGo Zero 式扩展应显式定义训练目标和数据来源，例如从搜索访问分布学习 policy、从实际轨迹回报学习 value；简单调用 JEV 或多跑几次搜索不等于完成该训练。训练模式与冻结模式分开实验，禁止使用测试任务训练或调参。

## 5. 真实环境、分支与停止

- 先确认环境能否 clone、snapshot/restore 或可靠 reset/replay；为复原保存必要随机状态，并将复原成本计入相应账本。
- 同一父节点的候选需要从相同或明确可比的状态出发。随机转移要记录随机性，不能仅凭相同动作假定相同后继。
- 互斥分支中的世界变化不能合并成一个已实现的世界。跨分支知识只有在适用前提成立时才可复用，并保留来源、条件和推导标识。
- 环境不可恢复时，采用明确标注的在线规划/行动模式；若引入模型模拟，其输出是预测，不能标为真实实验结果。
- benchmark 提供的客观成功信号用于实际完成判断；JEV 用于辅助评估答案充分性、规划进展或决定是否尝试提交。JEV 判断成功而环境未完成时，不能计为真实成功。
- 区分 `success`、`budget_exhausted`、`environment_failure` 等结束原因。预算耗尽时允许输出部分结论和未决问题，不将其计为任务成功。

## 6. 对比方式：建议的首轮协议

以下是为检验研究问题建议的默认设计，不代表已经完成实验，也不把某一种具体公式或超参数固化为用户要求。

| 方法 | 目的 |
| --- | --- |
| B0：LLM 顺序行动/研究循环 | 同一任务和工具下的基础能力，不使用 JEV 或树搜索 |
| B1：LLM + JEV 候选重排，逐步贪心执行 | 分离单步评估器的收益与树搜索的收益 |
| B2：LLM + MCTS，无 JEV | 分离树搜索收益；显式记录所用环境回报、rollout 或基础 LLM 价值启发式 |
| B3：LLM + JEV + MCTS 完整方法 | 检验两者结合是否带来额外收益 |

必要时补充相同预算的多次独立尝试、best-of-N 或 beam search；明确重置权限、选择答案所用评分器及其成本。不能只与一次便宜调用比较，便把增益归因于算法结构。

公平性要求：

- 优先在**同一生成 backbone 内**比较方法，固定任务实例、seed 集合、可见观测、工具权限、动作粒度及允许的环境恢复能力。
- 同基座的生成与评估应分别记录模型/adapter/head 的实际调用模式。共享底座结构不自动意味着共享一份运行时显存或 KV cache。
- 文本与 VL、不同模型规模和不同 SemIf 底座分别构成实验条件。不要将额外视觉信息或更大的模型算作搜索算法的收益。
- 在开发划分选择超参数，测试集只用于最终评测；不向模型开放仅供计分的隐藏标签或状态。
- 预先声明主预算及各硬上限，同时报告真实消耗。统计生成与 JEV 调用、输入/输出 token、环境 step、rollout、reset/replay/clone、耗时和必要的显存信息。
- 搜索期间试过但最终未提交的动作也计入环境交互成本；仅对齐最终轨迹长度不足以保证公平。
- 候选数量、搜索次数、最大深度、rollout 长度、剪枝规则和停止阈值是可记录的实验参数，不应为每个测试任务临时调优。

主要指标采用各 benchmark 的客观成功率/任务得分；同时报告失败类型、环境步数与推理成本。对研究问答另评估答案正确性和证据支持程度，避免仅用参与搜索的同一个 JEV 自评。采用多 seed/任务样本，报告样本量、波动或置信区间，以及预算—效果关系；不将四种环境的原始分数直接平均。

建议消融分别关闭候选筛选、后继状态评估、JEV 停止辅助、证据工作记忆策略，并对比 MCTS 与贪心/广度策略。单因素消融尽量固定其余接口和预算，记录移除某环节后的替代行为。

## 7. 实现推进与记忆维护

建议推进顺序（不是已完成清单）：

1. 定义状态、动作、证据、环境能力与预算契约，跑通一个任务的最小闭环（AR-0/3/4/5/7）。
2. 建立 LLM 顺序基线和统一轨迹/成本记录（AR-2、EVAL）。
3. 实现分支选择、扩展、叶评估与回传，检查可恢复环境中的分支隔离（AR-1/6）。
4. 接入可独立开关的 JEV 角色，贯通完整无训练方法（AR-2/5/6/7）。
5. 扩展四个 benchmark，完成等条件对比和消融（EVAL）。
6. 有需要再开启 value/policy 学习，保持无训练路径可独立复现（TRAIN）。

截至本文件建立时，仓库已有环境与模型配置；本文件不宣称上述算法阶段已经完成。每次任务以实际代码与验证记录重新定位，不把静态日期当作实时进度。

新的稳定决策在本文件相应位置更新；临时日志、测试、实验输出按现有发布目录规范保存。本文件及技能是开发协作记忆，可随 `.agents/` 在发布包中排除，正式运行代码不能依赖它们。
