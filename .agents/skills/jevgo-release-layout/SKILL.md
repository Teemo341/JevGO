# JevGO 发布与开发目录规范

用户要求开源交付只保留必要的运行代码。开发时可以写测试、探针和维护工具，但它们不得混入最终发布目录；发布时移除整个 `.dev/`。

## 文件归属

- **发布保留**：业务实现、用户实际调用的安装/运行入口、必要配置与锁文件、最简使用说明、许可证。当前 `scripts/` 只保留 `bootstrap.sh`、`env.sh`、`verify_offline.py`；后续新增文件按实际用途判断，不按名称判断。
- **开发临时**：测试、smoke、兼容性探针、调试脚本、构建/导出/抓取工具、测试样例、实验结果和日志，统一放在 `.dev/`。目录约定：`tests/`、`tools/`、`fixtures/`、`artifacts/`、`cache/`、`tmp/`；只在实际需要时创建。
- `.venv/` 是生成的运行环境；`.tools/`、`.cache/offline/` 和 `.third-party/autotrust/` 是当前离线交付资源。它们不因名称包含 cache 或 third-party 就成为可删的开发垃圾。保留的 wheel、固定源码归档、补丁和来源哈希支持离线重建，不提交大体积二进制到 Git。
- 本技能与 `AGENTS.md` 是长期项目协作规则，保留在开发仓库；不属于用户运行脚本，发布包可排除。

## 开发时

1. 写文件前先判断：删除它是否会影响用户安装、正常运行或必要资源校验？会影响的留在正式目录；仅为开发者验证或产生正式文件的放 `.dev/`。
2. 正式代码不得导入、执行或读取 `.dev/` 中的文件；正式使用说明也不得要求读者运行开发测试。`verify_offline.py` 被安装入口调用，是发布代码；`verify_semif_source.py` 仅服务测试，属于开发代码。
3. 测试默认输出、随机小模型、调试日志和构建临时目录写入 `.dev/`。程序正常运行生成的缓存可以使用运行时缓存目录，但不得把 `.cache/offline/` 当临时目录清理。
4. 移动文件时同时更新项目根定位、相对导入、调用路径、默认输出目录和文档引用。离线 manifest 不得收录 `.dev/`；移动清单中的测试资产后同步清单，不能保留指向旧位置的条目。
5. 保留来源不明的用户文件；不剥离第三方 wheel 或固定源码归档内部的文件。不要为仅移动代码而重新下载依赖、模型或更改锁定版本。

## 准备发布时

- 在发布副本中删除或排除 `.dev/` 及开发协作元数据，不提前删除仍在使用的开发工作区。`.gitignore` 避免提交本地开发产物；`.gitattributes` 的 `export-ignore` 只作用于 Git 归档，不能代替普通复制时的排除操作。
- 检查发布入口、配置、资源清单和使用说明没有开发目录依赖。验证发布副本缺少 `.dev/` 后仍可运行 `bootstrap.sh`、`env.sh jevgo --check` 和必要的最小运行命令。
- 验证程序和验证输出本身仍放在开发区；通过后再交付发布副本。文件归类整理不等于已经发布，不自动提交、推送或上传。
- 当前安装默认离线；离线交付须携带保留工具和 wheel，Git clone 本身不含这些文件。不要把源码仓库和完整离线包混为一谈。

开发命令与当前目录布局见项目根目录 `.dev/README.md`；用户用法只维护在 `docs/environment.md`。
